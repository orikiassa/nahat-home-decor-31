# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

"נחת Home" (Nahat Home) is a Hebrew/RTL e-commerce storefront for a home-decor brand, built with TanStack Start (React 19 + TanStack Router, SSR) and deployed to Cloudflare via Wrangler. It was scaffolded and is iterated on through Lovable (see `.lovable/plan.md` for the most recent in-flight plan/feature description). Product catalog, cart, and checkout are backed live by the Shopify Storefront GraphQL API.

## Commands

Package manager is **bun** (`bun.lockb` is the lockfile of record; `package-lock.json` also exists but bun is primary — `bunfig.toml` sets `saveTextLockfile = false`).

- `bun install` — install dependencies
- `bun run dev` — start the Vite dev server (TanStack Start)
- `bun run build` — production build (via `@lovable.dev/vite-tanstack-config`, includes Cloudflare plugin)
- `bun run build:dev` — build in development mode
- `bun run preview` — preview a production build
- `bun run lint` — run ESLint over the repo
- `bun run format` — format the repo with Prettier

There is no test suite/framework configured in this repo currently.

## Architecture

### Routing
File-based routing via TanStack Router. Route files live in `src/routes/` and `src/routeTree.gen.ts` is **generated** — do not hand-edit it (it's regenerated by the TanStack Router Vite plugin, wired up inside `@lovable.dev/vite-tanstack-config`). `src/router.tsx` creates the router instance and defines the default error boundary; `src/routes/__root.tsx` defines the document shell (`<html lang="he" dir="rtl">`), global `<head>` metadata, and the 404 component.

Key routes:
- `/` (`routes/index.tsx`) — homepage; fetches the live product list from Shopify client-side.
- `/product/$handle` (`routes/product.$handle.tsx`) — the real product detail page, fetched from Shopify by handle. Supports an image gallery (main image + thumbnails) and variant selection.
- `/products/$productId` (`routes/products.$productId.tsx`) — a **legacy/static** product page driven by the hardcoded catalog in `src/lib/products.ts`. Not linked from the live Shopify product flow; treat as vestigial unless asked to wire it up.
- `/about`, `/faq` — static content pages.

### Shopify integration (`src/lib/shopify.ts`)
All product and cart data comes from the Shopify **Storefront** GraphQL API, called directly from the client via `storefrontApiRequest()`. Store domain, API version, and the public Storefront access token are hardcoded constants at the top of the file (this is the public storefront token, safe for client-side use — not the Admin API). GraphQL queries/mutations for products, a product by handle, and cart create/lines-add/lines-update/lines-remove all live in this one file. A `402` response is treated specially (Shopify billing not active) and surfaces a toast instead of throwing.

### Cart state (`src/stores/cartStore.ts` + `src/hooks/useCartSync.ts`)
Cart is a Zustand store (`useCartStore`) persisted to `localStorage` under the key `shopify-cart` (only `items`, `cartId`, `checkoutUrl` are persisted). The store is the single source of truth for cart mutations and always mirrors state to the real Shopify cart via the mutations in `shopify.ts`:
- `addItem` creates a Shopify cart on first add, then adds/updates lines on subsequent adds.
- `updateQuantity` / `removeItem` mutate the Shopify cart directly.
- Any mutation that gets a "cart not found" error from Shopify (e.g. an expired/abandoned cart) clears local cart state via `clearCart()`.
- `syncCart()` re-fetches the remote cart to reconcile quantity/existence; `useCartSync()` (used in `SiteHeader`/root layout) runs this on mount and whenever the tab becomes visible again, so a cart emptied/changed elsewhere (e.g. completed checkout) is reflected back into the UI.

Checkout is handed off entirely to Shopify: `checkoutUrl` returned from `cartCreate` is the redirect target (with `channel=online_store` appended by `formatCheckoutUrl`).

### UI components
- `src/components/ui/` — shadcn/ui primitives (Radix UI + `class-variance-authority` + Tailwind). Configured via `components.json` (style: "new-york", no RSC, path aliases below). Treat these as generated/vendored — prefer composing them over rewriting.
- `src/components/` (top-level) — app-specific components: `SiteHeader`, `SiteFooter`, `ProductCard`, `CartDrawer`.
- Styling is Tailwind CSS v4 (`@tailwindcss/vite` plugin, config-free — theme lives in `src/styles.css`), with `tailwind-merge`/`clsx` combined in `src/lib/utils.ts` (`cn()`).
- Path alias `@/*` → `src/*` (see `tsconfig.json`, `components.json`).

### Language/locale
The entire UI copy is Hebrew and the document direction is RTL (`dir="rtl"` set in `__root.tsx`). Keep new user-facing strings in Hebrew and RTL-aware in layout (e.g. use logical Tailwind classes/flex direction rather than assuming LTR) to stay consistent with the rest of the app.

### Deployment
Cloudflare Workers, configured via `wrangler.jsonc` (`nodejs_compat`, entry `@tanstack/react-start/server-entry`). The Cloudflare Vite plugin is wired in automatically by `@lovable.dev/vite-tanstack-config` — do not add it again manually in `vite.config.ts`.

## Conventions

- `vite.config.ts` delegates almost everything to `@lovable.dev/vite-tanstack-config`, which already wires up TanStack Start, React, Tailwind, tsconfig paths, Cloudflare (build-only), Lovable's component tagger (dev-only), `VITE_*` env injection, the `@` alias, React/TanStack dedupe, error logging, and sandbox port/host detection. **Do not re-add any of these plugins manually** — see the comment block in `vite.config.ts` itself.
- Prettier config: 100 char print width, double quotes off (`singleQuote: false` → double quotes), semicolons on, trailing commas everywhere (`.prettierrc`). `eslint.config.js` runs `eslint-plugin-prettier` as part of lint, so `bun run lint` will also flag formatting issues.
- TypeScript strict mode is on, but `noUnusedLocals`/`noUnusedParameters` and the ESLint no-unused-vars rule are both explicitly disabled — unused vars are not treated as errors in this repo.
- `src/assets/` holds imported product/hero images bundled by Vite; these are distinct from the live Shopify product images (which are remote URLs from the Storefront API).
